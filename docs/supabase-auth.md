Supabase Auth is the sole hosted login. No HTTP Basic challenge, legacy credentials or public account linking. Unbound workspace and private routes redirect to /login (APIs return 401). An authorized Supabase administrator creates the confirmed non-anonymous email/password account and explicitly binds its UUID to the existing public.users workspace row (00000000-0000-4000-8000-000000000001). This keeps the reports' owner UUID unchanged. Verify identity before binding; never auto-bind the first registered account. The admin can use SQL Editor with an exact verified UUID and WHERE auth_user_id IS NULL. Remove APP_ACCESS_USERNAME and APP_ACCESS_PASSWORD from Vercel after production rollout. Local SQLite remains available locally, but Vercel fails closed if misconfigured. User session validated with getUser and a matching owner UUID. No public signup UI or self-service reset. No password should be shared in chat or committed. Existing auth tables and RLS remain unchanged.
